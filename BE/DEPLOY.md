# Deploy the backend to Render

Target: Render web service (Docker, Singapore) + Supabase Postgres (Tokyo) + FE on Vercel.

## 0. Before the first deploy (do once)

1. **Supabase → Project Settings → Database → Reset database password.** The old one was shared in chat.
2. Copy the **Session pooler** connection string (port 5432, user `postgres.<ref>`), not the direct one.
3. Change the seed passwords (`ChangeMe@123`) of `admin@` and `manager@` at least.
4. Push the `BE/` folder and `render.yaml` to GitHub.

## 1. Create the service

1. Render Dashboard → **New → Blueprint** → select the repo → it reads `render.yaml`.
2. Fill the prompted variables:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the session-pooler string from step 0 |
| `CORS_ORIGINS` | `["https://<your-app>.vercel.app"]` (exact FE origin, no trailing slash; add a custom domain too if any) |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | Supabase Storage for customer uploads (service_role key; secret, server-only). Bucket `order-inputs` is created automatically. |
| `GOOGLE_CLIENT` | optional (old name `GOOGLE_CLIENT_ID` still read): Google OAuth **Web** client id(s), comma separated, to enable `POST /auth/google`. Without it that endpoint answers 503. Add the FE origin to "Authorized JavaScript origins" in Google Cloud Console. |
| `CORS_ORIGIN_REGEX` | optional, only to allow Vercel preview deployments, e.g. `https://<project>-[a-z0-9-]+-<team>\.vercel\.app` |

`JWT_SECRET` is generated by Render. Keep `ENABLE_DOCS=true` so Swagger stays at `/docs`.

3. Deploy. Each deploy first runs `alembic upgrade head` (pre-deploy), then starts one instance.

## 1b. Real payments and carriers (optional; default is simulated)

Out of the box (`PAYMENT_MODE=mock`, `CARRIER_MODE=mock`) nothing leaves the server: payments and waybills are simulated and
labelled `MOCK`. To use the real VNPay / MoMo / GHN APIs, add these variables in **Render → Environment** (they are not
in `render.yaml`; they are secrets) and redeploy. **Run `alembic upgrade head` first** (the deploy does it) so migration `0004`
exists before the new code reads the order's `shipping_*` columns.

| Variable | Meaning |
|---|---|
| `PUBLIC_BASE_URL` | public `https` address of this API, e.g. `https://ai-vhrs-be.onrender.com` (no trailing slash). The gateways and carriers call back to it |
| `PAYMENT_MODE` | `mock` (default) / `sandbox` (the gateways' TEST environments, test money) / `live` (**real money**: only with production credentials and the owner's say-so) |
| `PAYMENT_RETURN_URL` | web-app page the customer is sent back to after paying, e.g. `https://<app>.vercel.app/payment/result` (display only) |
| `PAYMENT_EXPIRE_MINUTES` | payment link lifetime, default 15 |
| `VNPAY_TMN_CODE`, `VNPAY_HASH_SECRET` | from VNPay (sandbox: email after registering at sandbox.vnpayment.vn/devreg) |
| `VNPAY_PAY_URL`, `VNPAY_API_URL` | default to the sandbox addresses; set the production ones for `live` |
| `MOMO_PARTNER_CODE`, `MOMO_ACCESS_KEY`, `MOMO_SECRET_KEY` | from MoMo for Business (test environment keys differ from production keys) |
| `MOMO_ENDPOINT` | default `https://test-payment.momo.vn`; `https://payment.momo.vn` for `live` |
| `PAYOS_CLIENT_ID`, `PAYOS_API_KEY`, `PAYOS_CHECKSUM_KEY` | payOS (VietQR bank transfer): my.payos.vn → Kênh thanh toán → the channel's integration info. **payOS has no test environment: every payment is a real transfer**, so it is available as soon as the three keys are set, whatever `PAYMENT_MODE` says. `PAYOS_BASE_URL` defaults to `https://api-merchant.payos.vn` |
| `CARRIER_MODE` | `mock` (default) / `sandbox` / `live` |
| `CARRIER_WEBHOOK_SECRET` | long random string GHN's callback carries, in the address (`?key=`) or in a custom header (`X-Webhook-Secret`); GHN does not sign its callbacks |
| `GHN_TOKEN`, `GHN_SHOP_ID` | GHN API token and shop id. The pick-up address is the shop's own address registered with GHN (Developer Portal): no district/ward variables. The same credentials feed the address pickers (`GET /locations/...`) |
| `GHN_BASE_URL` | default is GHN staging; `https://online-gateway.ghn.vn/shiip/public-api` for `live` |

Also switch GHN's API on in the database: `system_settings.integrations_enabled` (`{"GHN": true, ...}`).
While the flag is `false` GHN is offered with one option priced from the fallback fee table. GHTK was dropped from the flow
(2026-10-26): its flag is ignored and its value stays in the `carrier` enum only so old rows keep reading.

**payOS first:** run `alembic upgrade head` (migration `0005` adds `PAYOS` to the `payment_gateway` enum; the deploy does it), set the
three `PAYOS_*` keys and `PUBLIC_BASE_URL`, redeploy, then register the webhook once from a shell that has the same environment:
`python scripts/register_payos_webhook.py` (payOS posts a test message to `POST /api/v1/webhooks/payments/payos` and the API answers 200).
Do it again if `PUBLIC_BASE_URL` changes.

**Register the callbacks with each provider** (they cannot be set from this API):

| Provider | Address | Where / how |
|---|---|---|
| VNPay | `https://<PUBLIC_BASE_URL>/api/v1/webhooks/payments/vnpay/ipn` | IPN URL in the VNPay merchant admin (sandbox: the merchant portal link in the registration email) |
| MoMo | sent with every payment (`ipnUrl`); no registration | the address must be public `https`; allow MoMo's source IPs if you filter |
| GHN | `https://<PUBLIC_BASE_URL>/api/v1/webhooks/shipments/GHN?key=<CARRIER_WEBHOOK_SECRET>` | self-service: Developer Portal (developer.ghn.vn for production, developer.ghn.dev for staging) > account menu > Webhook configuration > Order tab: paste the address, press Create webhook. A secret in a custom header (`X-Webhook-Secret: <secret>`) works instead of `?key=`. Staging and production are separate accounts; a change takes ~15 minutes. GHN retries 5xx/408/429 and drops other 4xx |

**First real run (nothing has been run against the providers yet):** use `sandbox`, make one small deposit with each gateway and
one waybill with GHN, and check the Render logs. GHN's preview / create / cancel / label token / master-data calls were run
against its staging API on 2026-10-26; its callback has not yet reached this server. The adapters' notes (`integrations/vnpay.py`,
`momo.py`, `ghn.py`: "VERIFICATION") list exactly what is proven and what is not. Do not set `live` before that.

## 2. Verify

```bash
curl https://<service>.onrender.com/api/v1/health      # {"status":"ok"}
```

Open `https://<service>.onrender.com/docs`, **Authorize** with an account, call `GET /api/v1/me`.
Response headers must include `strict-transport-security` and `x-content-type-options`.

## 3. Connect the FE (Vercel)

Set the FE env var that holds the API base URL to `https://<service>.onrender.com/api/v1`
and redeploy the FE. Browser calls only work for origins listed in `CORS_ORIGINS`.

## Operating notes

* **One instance only.** The rate limiter is in memory; scaling out needs Redis first.
* Free plan sleeps after inactivity and has no pre-deploy command; use at least `starter`
  so webhooks (VNPay/MoMo/GHN) are not missed.
* Logs: Render dashboard → Logs (the app writes to stdout).
* Rollback: Render → Events → pick a previous deploy. Migrations are not rolled back automatically.
* Tests write and delete `pytest_*@example.com` rows in the configured database, so run them
  against production only deliberately.
